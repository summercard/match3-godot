# 队长技能特效制作手册

本手册规定队长技能特效从规则、配置到验收的制作方式。当前阶段使用方形色块验证节奏、绑定和范围；替换贴图、序列帧或 GPU 粒子时，必须保留相同的层级、目标绑定和时间轴。

配置总表见 [队长技能特效配置表](队长技能特效配置表.md)，代码唯一来源是 [leader_skill_vfx_sequence_db.gd](../src/data/leader_skill_vfx_sequence_db.gd)。

## 1. 基础框架前置门槛

开始制作任何一个具体技能前，先检查工程是否已有以下基础框架：

| 必须先明确的内容 | 最低要求 | 当前工程位置 |
| --- | --- | --- |
| 特效层与绑定规则 | 明确释放、飞行、连线、受击各绑定谁 | 本手册第 2 节 |
| 数据来源 | 效果块与技能时间轴有唯一维护位置 | `leader_skill_vfx_sequence_db.gd` |
| 播放职责 | 配置负责时序；播放器负责绑定；渲染器只负责画；战斗负责结算 | 本手册第 3 节 |
| 目标范围 | 单体、全体、连锁目标如何展开 | `target_scope` / `source_scope` |
| 可验证入口 | 至少有可选择施放者/目标的测试页和自动测试 | `leader_skill_test.tscn` 与 `tests/` |

如果任何一项缺失，**先补规则与文档，再做单个技能效果**。至少要写出：层级表、绑定规则、配置字段、最小播放流程、测试入口与验收项。没有这些基础规则时，不应把某个技能的时序、坐标或随机逻辑直接写进场景脚本。

## 2. 四层与绑定原则

| 层 | 数据值 | 必须绑定 | 适合表达 | 不应承担 |
| --- | --- | --- | --- | --- |
| 自身释放 | `release` | 施放者中心 | 蓄力、起手、能量聚集 | 在目标身上出现结果 |
| 飞行 | `flight` | 起点 → 终点路径 | 火球、石块、箭、弹射物 | 持续牵引关系 |
| 连线 | `link` | 起点 → 终点路径 | 雷电、治疗束、吸取、锁定 | 独立的飞行物 |
| 受击 | `hit` | 目标中心或明确目标节点 | 爆炸、治疗、护盾、状态结果 | 替代施放动作 |

选择结构时先回答“玩家需要看见什么”：投射物使用 `release → flight → hit`；持续关系使用 `release → link → hit`；直接治疗或增益使用 `release → hit`。不为“看起来更炫”增加没有玩法含义的路径层。

## 3. 系统职责与数据流

```text
效果块库 + 技能时间轴
        ↓ build_playback()
带 from / to / center / delay 的运行时条目
        ↓ 场景排程
测试页 / 战斗场景的方块渲染器

战斗系统：仅在 get_impact_start() 对齐数值结算
```

- `EFFECT_BLOCKS` 定义可复用视觉语言：层、锚点、类型、颜色、尺寸和可调参数。
- `SKILL_SEQUENCES` 只排列步骤：`effect`、`start`、`duration` 及必要的范围/重复/运动覆盖。
- `build_playback()` 解析施放者、目标、全体目标和连锁目标；它生成运行时 `from`、`to`、`center`、`delay`。
- 测试页与战斗场景读取同一播放条目，不能各自写一套技能时间轴。
- 战斗伤害、治疗、状态和选目标属于战斗系统；特效配置只决定呈现，不改变数值规则。

## 4. 配置字段说明

### 每个效果块

| 字段 | 用途 | 规则 |
| --- | --- | --- |
| `layer` | 语义层 | 必填，且只能是 `release`、`flight`、`link`、`hit` 之一 |
| `anchor` | 视觉绑定点 | `caster`、`path`、`target`；必须与层一致 |
| `kind` | 渲染器分派 ID | 仅在外观或行为真正不同的时候新增 |
| `color` / `size` | 原型视觉参数 | 先用色块确认可读性，后续可替换真实资源 |
| `target_scope` | 目标展开范围 | 默认 `selected_target`；全体用 `all_targets` |
| `source_scope` | 路径起点来源 | 连锁第二段可用 `selected_target` |

### 每个时间轴步骤

| 字段 | 用途 | 规则 |
| --- | --- | --- |
| `effect` | 引用效果块 ID | 不能把完整视觉配置复制到场景代码 |
| `start` | 相对技能开始的秒数 | 所有时序以它为唯一来源 |
| `duration` | 可见持续时间 | 受击起点需与实际结算时刻对应 |
| `repeat_count` / `repeat_interval` | 连续实例次数与间隔 | 同一组连发的 release、flight、hit 必须同步使用 |
| `arc_degrees` | 抛物线角度 | 飞行主体与同节点拖尾须一致 |
| `random_arc_*` | 重复飞行的稳定随机弧线 | 在构建播放时固定，不能逐帧随机 |

## 5. 常用制作模式

| 模式 | 配置结构 | 关键约束 | 当前参考 |
| --- | --- | --- | --- |
| 抛物线投射 | `release → flight body + trail → hit` | 主体、拖尾共用起止、时长和弧线；受击在抵达时开始 | 火球 |
| 直接治疗 | `release → hit` | 没有飞行层；治疗柱与颗粒都在目标上 | 均衡 |
| 群体结果 | `release → hit(all_targets)` | 释放只一次，目标受击按目标数展开 | 治疗 |
| 连锁 | `release → flight(A→B) → hit(B) → flight(B→C) → hit(C)` | 第二段 `source_scope` 必须为第一目标 | 潮汐 |
| 连续投射 | `release×N → flight×N → hit×N` | 每发相对偏移一致；随机只在构建时生成 | 岩壁 |
| 持续连线 | `release → link + hit` | 端点固定；连线与受击可并行持续 | 疾风 |

## 6. 随机、曲线与持续效果

- 所有粒子分布和重复投射的随机值使用 `stable_noise()`；不要在绘制函数内调用随机数。
- `sample_flight_motion()` 提供飞行位置、切线方向和本地 Y 轴朝向。将来接入箭或火球贴图时，贴图 Y 轴应朝飞行前方。
- `sample_lightning_link()` 保持 A、B 两端不动，只让中段折线随播放进度变化；持续连线不是飞行物。
- 重复投射可在每次施放时产生新排列，但一旦进入播放条目，弧线、左右方向和翻滚方向必须固定至该次播放结束。
- 连线或受击需要持续多久，就把相同的 `duration` 配在对应步骤；不要在渲染器中隐藏固定时长。

## 7. 制作与验收流程

1. 先检查第 1 节基础门槛；缺项时先补文档和最小框架。
2. 用第 2 节选定表现结构，明确谁释放、路径从哪到哪、谁受击。
3. 在效果块库新增或复用视觉块，在时间轴中组合；不要把时间写进场景。
4. 先用方形色块在测试页确认施放者、目标、节奏和范围。
5. 同步更新配置表：写明每一步的 `start / duration`、目标范围与重要随机规则。
6. 为新的结构或时序补回归断言，再运行自动检查。

验收时至少确认：

- 释放在施放者，飞行/连线的端点正确，受击在目标。
- 目标范围、连锁起点和重复次数符合配置。
- 数值结算对齐 `get_impact_start()`；渲染器没有另写等待时间。
- 同一次播放的随机粒子和轨迹稳定；下一次施放允许有新的排列。
- 当前原型没有偷偷加载贴图；替换正式资产后仍保留同一配置 ID 与时序。
