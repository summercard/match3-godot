# 游戏代码健康度审查与修改方案

日期：2026-05-18

范围：本次审查覆盖游戏功能完整性、表现体验、数值成长体验三个维度。检查方式包括代码阅读、资源目录核对、Godot headless 测试，以及对存档、战斗、结算、关卡、道具、教程、成长数据的重点抽查。

## 一、检查结论

当前工程已经具备较完整的游戏主循环：开始页、主界面、关卡选择、战斗准备、三消战斗、结算、队伍、图鉴、背包、商店、牧场、成就、签到、设置等模块基本存在，素材迁移也已经覆盖主要场景。

但从发布级可玩性看，仍有几类高优先级问题：

1. 战斗输入链路不稳定，`battle_input_test.gd` 的 viewport 输入派发路径失败，说明真实鼠标/触摸事件和内部拖拽逻辑之间仍有风险。
2. 存档链路有字段不一致和测试污染风险。结算场景大量使用 `stageId`，战斗结果部分使用 `stage_id`；P0 smoke 测试会写入真实 `user://save_game.cfg`。
3. 教程模块还没有真正接入存档和场景切换，属于“有 UI 框架但流程未闭环”。
4. 数值经济有明显漏洞：扫荡奖励固定为 160 金币/72 经验；金币箱商店价格 150 金币、使用获得 200 金币，存在正收益循环。
5. 成长反馈和战斗数值存在脱节：战斗里玩家等级有最低 5 级兜底，前期升级奖励对战斗强度的反馈会变弱。
6. 牧场和队伍战斗表现存在实际功能断点：牧场放置按钮参数类型错误，队伍界面与战斗界面的怪物图片映射不一致。

   P2 已接入屏幕 shake、敌我受击闪烁、敌方攻击目标反馈和 combo 文本，但仍主要依赖 draw UI 的基础动效。后续需要接入可配置特效、音效和更细的命中节奏。

   例如技能 ready、教程按钮、扫荡、捕获道具自动使用等功能存在 UI 表现，但玩家可控性和真实逻辑闭环还不够清晰。

## 五、维度三：数值成长体验

### 当前成长公式

- 玩家升级经验：`80 + level * 10`
- 怪物升级经验：同玩家公式
- 怪物属性成长：`baseStat * (1 + (level - 1) * rarityGrowthRate)`
- 稀有度成长率：1 星 0.08，2 星 0.10，3 星 0.12，4 星 0.14，5 星 0.16

### 数值问题

1. 前期奖励偏慢，但战斗强度又被等级兜底稀释  
   已将 1 级升级需求调至 90，第一关奖励调至 45 金币/45 经验。玩家两次首关胜利即可升级，早期经验条推进更明显。

2. 怪物进化周期偏长  
   已将战斗结算中的上阵怪物经验从关卡经验的 50% 提升到 100%，并提高牧场前期挂机收益，保证早期能看到怪物等级成长。

3. 商店存在金币正收益漏洞  
   `gold_chest` 售价 150 金币，使用后获得 200 金币，玩家可反复购买并净赚金币。金币类道具不应使用金币购买，或售价必须高于收益且有其他消耗理由。

4. 扫荡奖励不随关卡成长  
   固定 160 金币/72 经验会让早期 3 星关卡价值过高，同时让后期扫荡缺乏意义。

5. 进化石掉落目标不匹配  
   掉落表包含 earth/wind/dark 进化石，但初始三只需要 fire/water/grass。玩家最早最关心的成长目标无法通过自然战斗掉落稳定推进。

6. 捕获系统对玩家选择权较弱  
   捕获会倾向自动消耗最好的捕获道具。虽然降低操作复杂度，但玩家可能无法决定是否节省高级道具。

### 数值修改方案

| 优先级 | 修改项 | 建议 |
|---|---|---|
| P0 | 修复金币箱正收益 | 已移除 `gold_bag/gold_chest` 的金币商店购买路径，保留为掉落道具 |
| P0 | 扫荡奖励绑定关卡 | 已使用关卡奖励、星级倍率、扫荡倍率计算扫荡收益 |
| P1 | 前期升级反馈 | 已校准：两次首关胜利可触发玩家升级，上阵怪物同步获得完整关卡经验 |
| P1 | 进化石投放 | Ch1-Ch3 投放 fire/water/grass，Ch4 以后再扩展 thunder/light/dark 等 |
| P1 | 怪物经验补偿 | 让上阵怪物至少获得关卡经验的 100%，未上阵怪物可获得 20%-30% |
| P2 | 数值模拟 | 增加脚本模拟 1、5、10、30、60 分钟玩家成长、金币、经验、进化进度 |

## 八、补充深度审查：牧场与队伍战斗表现

本节是针对实际游玩反馈追加的链路检查，重点不是“模块是否存在”，而是“玩家操作是否能真正驱动存档和表现”。

### 1. 牧场功能链路

代码链路：

`scene_ranch.gd init -> _load_data -> _build_picker_buttons -> _on_picker_item_pressed -> _save_ranch_state -> _calc_idle_exp -> _on_collect_pressed`

发现的问题：

1. 放置入口类型错误  
   `_build_picker_buttons()` 从 `_captured_monsters` 里拿到的是字符串 ID，例如 `"monster_001"`。但点击回调 `_on_picker_item_pressed(monster_id: int)` 把参数声明成 `int`。这会让按钮点击与真实数据类型不匹配，属于牧场不能使用的直接风险。

2. 气泡函数参数也错  
   `_add_bubble(slot_index: int, monster_id: int)` 同样把怪物 ID 写成 int。虽然函数内部暂时没使用 monster_id，但这是同一类移植遗留问题。

3. 收取按钮状态不完整刷新  
   `_update_collect_button()` 只在初始化里调用。放置、移除、收取后虽然重建了槽位，但没有稳定刷新按钮状态和详情面板，容易出现“明明有收益/已经收取，但按钮表现不对”的问题。

4. 存档字段命名有双轨风险  
   SaveManager 已统一输出 `monster_id/placed_at/unlocked_slots`，并在读取旧存档时兼容 `monsterId/placedAt/unlockedSlots`。场景层现有兼容逻辑可以保留为防御层。

建议修复：

- 把 `_on_picker_item_pressed(monster_id: int)` 改为 `_on_picker_item_pressed(monster_id: String)`。
- 把 `_add_bubble(slot_index: int, monster_id: int)` 改为 String，或去掉未使用参数。
- 每次放置、移除、领取后调用统一刷新函数：重算收益、重建槽位、重建列表、更新详情、更新收取按钮。
- 给牧场新增 headless 测试：模拟捕获列表、放入怪物、写存档、推进 placed_at、领取经验、重进场景验证状态。

`scene_team.gd save_team -> SaveManager.load_team -> scene_battle.gd _init_battle -> BattleManager.init -> scene_battle.gd _draw_player_card -> _get_monster_texture`

发现的问题：

1. 队伍界面和战斗界面的图片表不一致  
   `scene_team.gd` 的 `MONSTER_ASSETS` 包含：

   - `monster_001`
   - `monster_002`
   - `monster_003`
   - `monster_004`
   - `monster_005`
   - `monster_006`
   - `monster_007`
   - `monster_017`
   - `monster_boss_001`

   `scene_battle.gd` 的 `MONSTER_IMAGE_PATHS` 只包含：

   - `monster_001`
   - `monster_002`
   - `monster_003`
   - `enemy_001`
