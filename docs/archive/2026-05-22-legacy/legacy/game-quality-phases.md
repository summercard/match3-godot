# 游戏质量优化计划（优质开发者视角）

## 创建条件
当 docs/phase5-priority-fixes.md 的 5 个阶段全部完成后，自动进入此计划。

## 原则
站在**玩家体验**角度，以**发布级品质**为目标持续优化。
不是"能跑就行"，而是"玩起来舒服"。

## 阶段划分

### Phase 1: 交互手感优化
- [ ] 按钮点击反馈优化（按下缩放 + 松开回弹，缓动曲线 ease-out-back）
- [ ] 宝石滑动灵敏度调整（触摸死区、最小滑动距离、方向锁定）
- [ ] 宝石交换动画补间（位置插值 + 缓动，而非瞬间跳转）
- [ ] 棋盘下落动画缓动曲线（bounce 效果而非线性下落）
- [ ] 页面转场动画统一（所有页面进出用一致的淡入淡出+滑动）
- [ ] 滚动列表惯性优化（stage_select/album/inventory 等场景的列表滚动）
- **涉及文件**: 各 scene_*.gd, scene_manager.gd
- **参考**: 微信版各场景的 touchStart/touchMove/touchEnd 处理

### Phase 2: 视觉打磨
- [ ] 全局配色统一（检查所有场景的颜色是否来自 theme.gd，消除硬编码颜色）
- [ ] 阴影层次优化（文字阴影、卡片阴影、面板阴影统一风格）
- [ ] 间距/对齐审计（所有场景的 UI 元素间距和对齐是否像素级精确）
- [ ] 按钮风格统一（所有场景的按钮大小、圆角、颜色是否一致）
- [ ] 字体大小层级（标题/正文/辅助文字的字号是否分级统一）
- [ ] 怪物卡片样式统一（battle/ranch/album/evolve 中的怪物卡片风格一致）
- **涉及文件**: 各 scene_*.gd, theme.gd

### Phase 3: 战斗体验优化
- [ ] 消除反馈节奏感（消除→伤害弹出→敌人受击→新宝石落下的时间间隔调优）
- [ ] combo 视觉升级（高combo时屏幕震动加强、背景变色、音效配合）
- [ ] BOSS 战张力营造（BOSS 入场动画、血量变化时背景色变化、濒死特效）
- [ ] 属性克制视觉反馈（weak→大伤害红字，resist→小伤害灰字）
- [ ] 队长技能触发提示（技能触发时的视觉高亮）
- [ ] 敌方回合等待体验（显示敌方行动前的短暂"蓄力"动画，不让玩家干等）
- **涉及文件**: scene_battle.gd

### Phase 4: 游戏内容完善
- [ ] 新手引导流程优化（tutorial 场景交互更友好）
- [ ] 关卡难度曲线检查（stage_db.gd 数值是否合理递进）
- [ ] 成就系统完整性（achievement_db.gd 成就是否能正常触发和领取）
- [ ] 商店物品平衡（价格/效果是否有价值）
- [ ] 签到奖励吸引力（7天签到奖励是否合理递增）
- [ ] 进化系统体验（进化动画是否有仪式感）
- **涉及文件**: 各 *_db.gd, 对应场景

### Phase 5: 性能优化
- [ ] 减少不必要的 queue_redraw()（只在状态变化时重绘）
- [ ] 纹理缓存优化（频繁加载的纹理预加载）
- [ ] 粒子系统对象池（复用粒子对象而非每帧创建）
- [ ] 浮动文字数量上限（超出时回收最早的）
- [ ] 背景缓存（不变的部分用 SubViewport 缓存）
- [ ] 内存占用分析（检查是否有纹理泄漏）
- **涉及文件**: 各 scene_*.gd, animation_player.gd

### Phase 6: 边界情况处理
- [ ] 空队伍进入战斗的处理
- [ ] 背包满了还能获取物品的处理
- [ ] 网络断开/游戏意外关闭的数据保护
- [ ] 存档损坏的恢复机制
- [ ] 极端数值溢出的防护（伤害/血量/金币上限）
- [ ] 横屏/竖屏切换的布局适配
- **涉及文件**: save_manager.gd, 各场景的 init/输入处理

## 验收标准
- 每个优化都有对应的视觉/体验改善
- Godot headless 验证无报错
- 代码风格一致，无硬编码魔法数字
