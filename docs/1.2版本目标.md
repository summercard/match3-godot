## 1. 版本定位

1.2 的目标不是新增一套脱离养成的小游戏，而是让已经培养、进化和编队的精灵拥有稳定的后期验证场景。

- **共鸣塔**：99 层连续 PVE 远征。精灵的等级、技能职责、队伍配合和塔内构筑共同决定可到达的高度。
- **远行信箱**：大厅内独立存在的轻社交入口。玩家选择一只冒险精灵，向远方送出祝福，也会收到陌生冒险者的祝福邮件。

两个系统的职责必须保持分离：共鸣塔负责战斗与排行榜，远行信箱负责祝福、来信和领奖。塔每阶段的奖励可通过系统邮件投递到信箱，但信箱不依赖爬塔才可使用。

## 2. 版本目标

### 2.1 玩家体验目标

1. 通关主线第 8 关后，玩家在大厅发现可进入的共鸣塔与远行信箱。
2. 玩家带着已经培养的三只精灵，连续完成四波小怪和一波 Boss；HP、状态、技能充能和塔内构筑会持续继承。
3. Boss 后在三张肉鸽卡中选择一张，清晰感到自己的队伍被强化为不同流派。
4. 玩家能看到自己的最高通关层数与最高单回合伤害，并有一个明确的下一层目标。
5. 玩家能一键选择精灵送出祝福，看见星星飞往远方，并在回到大厅后收到陌生人的祝福邮件。

### 2.2 版本成功标志

- 共鸣塔第 1–5 层纵向切片完整可玩，连续波次期间不切换战斗场景。
- 99 层配置可生成，阶段奖励不会重复投递。
- 登塔榜和爆发榜均可展示本地玩家记录与模拟旅行者记录。
- 邮箱可完成选择精灵、送出祝福、飞星表现、未读提醒、阅读与领取附件。
- 塔奖励邮件与陌生人祝福邮件走同一领取保护，重复打开不会重复发奖。

### 2.3 验收标准

#### 功能与代码验收

1. **新增优先，不破坏旧链路。** 共鸣塔、邮箱、排行和模拟祝福以新的数据段、新模块、新场景实现；不得重命名、删除或改变既有主线、战斗、捕捉、星级、扫荡、牧场、进化、背包、签到与成就的既有功能口径。
2. **核心改动只能增加分支。** 如必须接入 `BattleManager`、`SaveManager`、`SceneResult` 或 `main.gd`，只能增加明确的 `mode=tower`、新场景映射或兼容字段；旧模式的输入、默认值、结果字段和奖励路径必须保持不变。
3. **存档向后兼容。** 旧存档首次加载后应只补充 `tower`、`mailbox` 等新数据段；不得丢失旧玩家、队伍、背包、牧场、关卡和奖励数据。新增奖励必须使用事务与收据，重复进入、重复点击、异常保存后重试均不得重复发奖。
4. **原功能回归。** 在 P0 资源基线修复后，P0 冒烟、主线战斗、关卡解锁、捕捉、奖励幂等、存档完整性、牧场社交等既有回归测试必须通过；新增共鸣塔和邮箱测试不得以跳过旧测试为代价。
5. **新增功能验收。** 必须覆盖：第 1–5 层连续波次、状态继承、安全点回退、Boss 三选一、99 层终局、登塔/爆发排序、塔奖励邮件防重、祝福发送次数、模拟来信、邮件附件领取与存档恢复。

#### 美术与体验验收

1. **正式场景。** 共鸣塔和邮箱必须以可编辑 `.tscn` 为正式 UI 源，并从 `PACKED_SCENE_MAP` 进入；不以调试绘制、临时页面或概念图直裁作为交付界面。
2. **风格统一。** 新资源使用正式 `assets/images/<page>_new/` 目录或已批准资源；禁止引用概念图目录、混用旧页面资源填空，或使用带棋盘格、白边、脏透明、模糊放大的图片。
3. **关键体验可感知。** 所有可点击控件必须具有按压/释放反馈；共鸣塔的下一波、Boss、三选一卡、安全点和阶段奖励投递需要清楚的状态变化；邮箱的精灵选择、送出按钮、星星飞往远方、未读红点和领取附件需要不依赖文字也能理解的表现。
4. **真实运行时验收。** 不能只在编辑器内检查。每个正式页面都要在 Godot 运行时以 375×667 截图验收，并检查中文可读、文字不乱码、不遮挡、不截断，布局无漂移、重叠或边缘裁切，当前页和选中状态清晰。
5. **完整体验路径。** 验收人员须亲自走通：大厅解锁提示 → 共鸣塔五波 → Boss 卡牌 → 奖励邮件；以及大厅邮箱 → 选冒险精灵 → 送祝福飞星 → 新邮件红点 → 阅读并领取。任一链路的反馈缺失、状态不一致或奖励不可解释，均不视为通过。

## 3. 共鸣塔设计目标

### 3.1 解锁与入口

- 解锁条件：`stage_1_8` 已通关。该条件集中配置；如“第八关”未来改为“第八章”，只改解锁 ID，不改塔系统。
- 大厅显示独立的共鸣塔入口；未解锁时展示条件，已解锁时展示“最高 X 层”。
- 排行榜在共鸣塔页面内展示，不占用主线关卡星级或成就分数的语义。

### 3.2 层级结构

| 内容 | 规则 |
|---|---|
| 常规阶段 | 每 5 层为一个阶段：第 1–4 层各为 3 个小怪，第 5 层为 1 个 Boss + 2 个小怪 |
| 场景 | 同一阶段的五波战斗保持同一张地图、同一战斗场景，只更新层数/波次标签与敌人 |
| 状态继承 | 我方 HP、技能充能、护盾、状态、塔内道具和已选增益跨波继承；敌方离场时清除敌方状态 |
| Boss 后 | 发放阶段奖励并弹出三选一卡牌；选择完成才可进入下一阶段 |
| 安全点 | 每个 Boss 后保存为安全点，允许退出后继续；失败回退到本阶段起点，不清空已领取的阶段奖励 |
| 终局 | 1–95 层为 19 个完整阶段；96–98 层为小怪，99 层为最终 Boss + 2 个精英随从 |

99 层与五层阶段不能整除。保留 99 层，并将第 20 阶段定义为四波终局，是本版本的明确设计决定；不为了整齐而增加第 100 层。

### 3.3 难度与养成关系

- 第 1 层强度从主线第 10 章后开始，作为后期精灵的第一个验证点。
- 低层主要验证等级、进化和基础队伍；中层强调技能职责、敌方意图和状态续航；高层依赖卡牌构筑与精灵协同。
- 每个阶段只改变有限的压力项：敌人等级、敌人组合、地图压力、Boss 意图或精英词缀，避免只堆 HP。
- 允许用不同精灵解决不同高层题目；不把单一高稀有精灵设为唯一解。

### 3.4 Boss 后三选一卡牌

卡牌仅在塔内生效，到本次远征结束或赛季重置时清除。每次展示三张、选择一张。

| 卡牌类别 | 设计职责 | 示例方向 |
|---|---|---|
| 塔内补给 | 解决连续战斗的续航 | 回复、护盾、净雾、复苏、技能充能 |
| 共鸣增益 | 放大精灵已有玩法身份 | 指定棋盘能量充能、守护强化、控场延长、特殊宝石收益 |
| 风险契约 | 形成冲层与爆发流派 | 伤害提高但受伤增加、低血增伤、Boss 破招加成 |

同名增益必须有叠层上限；高强度遗物必须唯一。塔内补给不能消耗玩家背包内的永久道具，防止资源库存直接决定排名。

### 3.5 排行榜

- **登塔榜**：先比较最高已通关层数；同层时比较累计玩家回合数，较少者在前。
- **爆发榜**：比较共鸣塔内的最高单回合伤害。
- 单回合伤害定义为一次有效换位开始、敌方行动前结束所造成的伤害总和；包含连锁、特殊宝石和该回合触发的技能，不包含跨回合 DOT。
- 1.2 首版使用明确标识的“旅行者回声”模拟数据。未来接入真实好友/全服数据时替换数据提供方，不改变榜单口径。
- 名次奖励不直接提供战力；资源奖励按通关层数里程碑发放，名次只提供展示性内容。

## 4. 远行信箱设计目标

### 4.1 入口与页面

- 大厅新增邮箱入口；有未读邮件时显示红点和数量。
- 邮箱是独立正式界面，包含“收件箱”和“送出祝福”两个区域。
- 收件箱可阅读、领取附件、标记已读，并保留有限历史。

### 4.2 送出祝福

1. 玩家从已拥有精灵中选择一只作为冒险精灵。
2. 点击“送出祝福”。
3. 选中精灵发光，一颗星星从精灵处飞向远方，播放成功反馈。
4. 记录一条送出历史，不要求玩家选择真实收件人。

精灵的属性、性格和生态身份决定祝福的视觉/文案主题，不决定祝福数值强度。初版不做自由文本、不做真实玩家间的直接道具转移。

### 4.3 收到祝福

收到的模拟邮件统一使用如下玩家可见语义：

> 远方一位陌生冒险者，托精灵给你送来了祝福。

附件从轻量池中随机产生：少量金币、少量共享经验、低价值战斗补给、低概率捕捉球、旅记或邮票。禁止在祝福池直接投放宝石、高级进化石或高价值稀有资源。每日发送次数、邮件数量和掉落权重必须配置化，不写死在 UI。

### 4.4 与共鸣塔的关系

- Boss 阶段奖励由“共鸣塔阶段补给”系统邮件投递到收件箱。
- 该邮件不算陌生人祝福，不占用每日祝福数量。
- 邮箱在未解锁或不参与共鸣塔时仍可独立运行。

## 5. 范围边界

### 1.2 必做

- 99 层共鸣塔、五波阶段、Boss 后三选一、状态继承、安全点。
- 登塔榜、爆发榜和模拟旅行者记录。
- 大厅邮箱、选择冒险精灵、送出祝福飞星、陌生人祝福邮件和系统奖励邮件。
- 邮件领取防重、塔阶段奖励防重、存档迁移和运行时 UI 验收。

### 1.2 不做

- 公会、聊天、实时 PvP、自由文字私信。
- 真实玩家间直接转移高价值道具。
- 排名专属战力奖励。
- 以背包库存作为共鸣塔战斗消耗来源。
- 在排行榜未具备可复算随机与服务端校验前宣称真实全服竞技。
