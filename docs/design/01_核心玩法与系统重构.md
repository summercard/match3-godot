## 1. 新核心循环

### 局内循环

1. 观察棋盘、敌方意图和当前捕捉状态
2. 选择一次交换
3. 结算消除、连锁、特殊宝石和棋盘机制
4. 给怪物分配能量并触发普通行动
5. 选择是否释放关键技能
6. 处理敌方意图、阶段变化和场地威胁
7. 决定继续输出、控场、塑盘或捕捉

### 局外循环

1. 推进章节
2. 捕捉或解锁新怪物
3. 调整队伍角色和能量结构
4. 培养等级、进化、羁绊
5. 回到更高压、更有机制辨识度的战斗

## 2. 棋盘设计

## 2.1 基础能量

棋盘只保留 5 种基础能量。工作名如下：

| 棋盘能量 | 当前兼容色 | 体验职责 |
|---|---|---|
| 炽能 | fire | 爆发、燃烧、破坏 |
| 潮能 | water | 续航、冻结、缓冲 |
| 生能 | grass | 扩散、毒性、成长 |
| 震能 | thunder | 节奏、连锁、打断 |
| 辉能 | light | 转化、保护、捕捉辅助 |

世界观属性可以继续包含暗、风、土、冰、虚空、时空、星耀、混沌等，但它们必须显式映射到棋盘能量或特殊规则。

当前实现中，旧怪物数据若没有显式配置 `boardAffinity`，会按以下兼容映射自动推导：

| 幻想属性 | 默认棋盘亲和 |
|---|---|
| fire | fire |
| water / ice | water |
| grass / earth | grass |
| thunder / wind / temporal | thunder |
| light / dark / void / star | light |
| chaos | fire |

战斗结算口径：

- `element`：用于世界观、属性克制、队长属性加成和敌我幻想属性关系。
- `boardAffinity`：用于消除宝石响应、技能充能、棋盘能量共鸣和状态来源判定。

## 2.2 消除语法

| 消除形态 | 基础结果 | 设计意图 |
|---|---|---|
| 3 消 | 触发对应能量行动和充能 | 保持爽快与可读 |
| 4 消 | 生成定向强化宝石 | 给玩家下一步布局目标 |
| 5 消 | 生成谱系宝石或大规模转化 | 奖励规划 |
| L/T | 生成纹章炸弹 | 奖励空间判断 |
| 连锁 | 累积场域共鸣 | 让好运转成可利用资源 |

特殊宝石不只负责“炸更多”，还要服务于构筑差异：

- 破盾队伍想要高频定向爆破
- 塑盘队伍想要转色与保留关键形状
- 捕捉队伍想要控制过量伤害并制造捕捉共鸣

## 2.3 场域共鸣

连锁和特殊消除产生 `resonance`。

`resonance` 是战斗中少量可控的额外资源，用于：

- 强化某些技能
- 触发章节场地效果
- 打开稀有捕捉条件
- 抵消部分 Boss 压力

它的职责是把三消中的高光时刻接到怪物构筑上。

## 3. 怪物设计

## 3.1 怪物数据的必要身份

每个可出战怪物至少有以下设计字段：

| 字段 | 作用 |
|---|---|
| 幻想属性 | 世界观、克制、章节归属 |
| 棋盘亲和 | 使用哪种基础能量充能 |
| 战斗角色 | 玩家对它的第一理解 |
| 主动技能 | 一个可操作的局内爆点 |
| 被动或羁绊 | 一个构筑理由 |
| 捕捉偏好 | 作为敌人时的理解点 |

## 3.2 第一批角色原型

| 角色 | 核心作用 | 举例 |
|---|---|---|
| 输出手 | 抓住窗口打爆发 | 高倍率单体、溅射 |
| 破局手 | 清障、破盾、拆机制 | 岩块破坏、护盾穿透 |
| 塑盘手 | 转色、造宝石、保留形状 | 生成 4 消起点 |
| 守护手 | 护盾、回复、减伤 | 护住 Boss 蓄力回合 |
| 猎手 | 捕捉、压制、读意图 | 降低逃脱、制造驯服窗口 |

同一个怪物可以兼有副职责，但主职责必须一眼可识别。

## 3.3 主动技能重构

主动技能应由效果结构驱动，而不是只靠文本名和倍率。

当前代码契约：

- `skill.type` 表示玩家理解的技能职责，第一批包括 `strike`、`ward`、`tempo`、`hunt`、`shape`。
- `skill.effects` 是实际结算效果数组，第一版已支持 `damage`、`heal`、`guard`、`weaken`。
- 旧技能若只有 `multiplier`，会自动归一为 `strike + damage`，避免迁移期破坏旧内容。

第一阶段可落地技能样例：

| 技能 | 类型 | 效果方向 |
|---|---|---|
| 火焰冲击 | `strike` | 高伤单体，目标处于灼烧时追加破盾 |
| 水之护盾 | `ward` | 给低血队友护盾，若本回合有潮能连锁则附带净化 |
| 藤蔓束缚 | `tempo` | 降低敌方下次意图强度，草系共鸣时延长 |
| 雷电箭 | `hunt` | 打断蓄力，成功时提高捕捉稳定度 |
| 星光爆裂 | `shape` | 将少量非关键宝石转为辉能并触发一次小范围清理 |

初始三只怪物必须在前 10 分钟就体现不同职责。

当前第一版已落地：

| 怪物 | 类型 | 当前效果 |
|---|---|---|
| 小火龙 | `strike` | 单体高伤，用于抓住克制窗口 |
| 水龟仔 | `ward` | 治疗最低血队友，并给下一次受击减伤 |
| 草苗儿 | `tempo` | 中等伤害，并束缚目标使下一次攻击降低 |

## 4. 敌人与 Boss

## 4.1 敌方意图

敌人行动要可读。

敌方下一回合至少应暴露一种意图信息：

- 普攻
- 蓄力
- 护盾
- 回血
- 污染棋盘
- 逃脱准备

玩家看到意图后才会产生“我这步要不要打断”的决策。

当前第一版代码契约：

- `EnemyIntentRules` 将敌人技能状态统一转换为 `enemy_intents`。
- 战斗 UI 敌人卡显示下一步意图标签。
- 已支持 `普攻`、`攻击后蓄力`、`蓄力释放`、`架盾`、`回血`、`眩晕`。
- Boss 蓄力释放会直接展示破招建议：束缚或守护。

第一版只做可读意图，不在此阶段改变敌方技能结算强度。

## 4.2 Boss 设计公式

Boss 由三层组成：

1. 一条主节奏，例如周期蓄力
2. 一个章节棋盘压力，例如毒雾或封锁
3. 一个需要队伍应对的破招点，例如破盾、打断或共鸣阈值

Boss 不应只靠高血量和高倍率延长战斗。

当前第一版代码契约：

- `ChapterMechanicRules` 为每章输出 `chapterMechanic`，包含玩法名、玩法话术、压力来源、玩家计划、Boss 主节奏、棋盘压力和破招点。
- `StageDB.get_chapter()`、`get_stage()`、`get_chapters()` 会返回已补全的章节/关卡机制字段，不要求每个旧关卡手动复制模板。
- 每个关卡会获得 `stageGoal`，用于描述本关玩家目标，例如破障、解锁、控雾、精英压力或 Boss 三层考题。
- Boss 关会获得 `bossLayers` 三段结构：主节奏、棋盘压力、破招点。
- 关卡选择页显示章节玩法主题；战斗准备页显示章节机制、本关目标和 Boss 三层提示。
- P2 机制提示必须按“战斗信息组件”处理，字号和触控区域不能低于普通按钮/状态 HUD 的可读级别。

第一版只建立可读模板和 UI 入口，不在此阶段强行重算所有中后期关卡强度。

## 5. 捕捉重构

## 5.1 捕捉窗口

捕捉由 `tamingWindow` 驱动。

窗口来自多种来源：

- 目标血量进入安全阈值
- 被指定状态压制
- 关键意图被打断
- 满足章节怪物偏好
- 过量伤害未超过风险线

当前第一版代码契约：

| 窗口状态 | 触发口径 | 捕捉意义 |
|---|---|---|
| `locked` | 目标血量高且未被压制 | 暂时不适合捕捉 |
| `unstable` | 目标半血附近或被压制 | 有机会，但稳定度较低 |
| `open` | 目标进入低血区 | 推荐捕捉窗口 |
| `prime` | 目标极低血但未被击倒 | 最佳捕捉窗口 |
| `overpowered` | 目标已被击倒 | 可尝试，但稳定度下降 |

战斗过程中会记录每个敌人的当前窗口和本场最佳窗口。胜利后的自动捕捉优先读取本场最佳窗口，而不是只根据最终 HP 做一次抽奖。这样玩家在局内压血、控场、避免过量伤害会逐步变成捕捉策略的一部分。

## 5.2 玩家动作与预设

第一阶段提供清晰动作，但不把战斗节奏切碎成弹窗选择。

- 战斗页底部提供“自动捕捉”开关
- 开关开启时，胜利后默认尝试捕捉
- 开关关闭时，本场不进行捕捉判定
- 捕捉球通过背包装备为默认捕捉道具
- 战斗页底部捕捉球道具栏可以临时切换本场使用的捕捉球
- 自动捕捉开启且捕捉球可用时，胜利结算会消耗当前选中的捕捉球并进行一次捕捉判定
- 自动捕捉开启但未选择捕捉球，或选择的捕捉球库存不足时，本场不进行捕捉判定，也不消耗道具
- 捕捉概率由目标稀有度、当前捕捉窗口、玩家与敌人等级差、连续失败保护和捕捉球加成共同决定；捕捉球加成为固定加法加成，最终概率第一版封顶 95%

这个方案的目标是让玩家在进入战斗前表达捕捉意图，在战斗中只做轻量切换，不频繁打断三消节奏。

高级猎手型怪物可以改变窗口生成方式，但基础体验先要清楚。

## 5.3 捕捉结果

失败不只显示“没中概率”，还要反馈失败原因：

- 状态不稳
- 伤害压得太狠
- 怪物警戒过高
- 道具等级不足

这样失败才会教会玩家下一次怎么抓。

当前第一版玩家可见反馈：

- 战斗页底部展示当前最佳捕捉目标的稀有度、棋盘能量亲和和技能定位。
- 捕捉结果返回 `reason` 与 `advice`，结算页展示失败原因和下一次建议。
- 成功后提示玩家去队伍界面查看该怪物的能量亲和与技能定位。

## 6. 关卡与章节

## 6.1 关卡目标组合

主线关卡由以下目标组合：

- 击败主要威胁
- 捕捉目标
- 清理场地威胁
- 在限制回合内完成破招
- 保持队伍状态

## 6.2 章节机制节奏

章节每次只引入一个主要新判断，再用精英和 Boss 做综合题。

建议前六章节奏：

| 章节 | 核心教学 |
|---|---|
| Ch1 | 能量、技能、捕捉窗口 |
| Ch2 | 特殊宝石与石块破局 |
| Ch3 | 敌方意图与打断 |
| Ch4 | 锁定宝石与队伍塑盘 |
| Ch5 | 护盾、破盾、属性构筑 |
| Ch6 | 扩散场地与资源取舍 |

Ch1 第一版切片已经重编为“一关一个可感知学习点”：

| 关卡 | 学习点 | 玩家应感知到的变化 |
|---|---|---|
| 1-1 能量响应训练 | `boardAffinity` | 消除对应棋盘能量会驱动怪物行动与充能 |
| 1-2 捕捉窗口练习 | `tamingWindow` | 压低血量会打开捕捉窗口，并获得捕捉球 |
| 1-3 守护与续航 | `ward` | 水龟仔可治疗最低血队友并提供减伤 |
| 1-4 藤蔓束缚 | `tempo` | 草苗儿可束缚敌人、降低下一次攻击 |
| 1-5 花叶兽的破招 | Boss 破招 | 首个 Boss 用蓄力与二阶段检验输出、守护、控场 |

## 6.3 关卡解锁

战斗地图不再默认全部开放。第一版解锁口径：

- 新存档只开放 `stage_1_1`。
- 主线关卡按前置主线关顺序解锁，通关前一关后开放下一关。
- 新章节第一关需要通关上一章 Boss。
- 精英关是支线挑战，通关前一主线关后开放，但不阻挡本章 Boss。
- 关卡选择页显示锁定节点，锁定关卡不可进入。

## 7. 局外成长

## 7.1 保留系统

- 怪物池
- 编队
- 等级
- 进化
- 商店
- 成就
- 签到
- 牧场
- 扫荡

## 7.2 重新赋义

| 系统 | 新职责 |
|---|---|
| 怪物池 | 构筑库，不只是收藏列表 |
| 进化 | 角色玩法升级，不只属性升级 |
| 牧场 | 轻量陪伴与定向培养 |
| 商店 | 解决短期策略资源，不直接卖胜利 |
| 扫荡 | 消化已掌握内容，不替代体验新机制 |

## 7.3 羁绊方向

羁绊优先做小而明确的改造：

- 改变一个技能分支
- 增强一个捕捉偏好
- 给某类棋盘机制提供应对

羁绊不先做全量随机词条。

当前第一版代码契约：

- `EcologyBondRules` 根据怪物属性和技能类型生成生态身份、战斗角色、捕捉偏好和羁绊提示。
- 图鉴底部“羁绊”页展示各生态收集进度、生态主题和对应章节方向。
- 图鉴怪物详情展示角色身份和生态归属。
- 队伍编成页展示当前队伍羁绊状态，例如输出、守护、控场齐备时触发“开拓羁绊”。
- 第一版先做可读身份与组队目标，不直接改写战斗数值，避免未验证前破坏 P0/P1 平衡。

## 7.4 牧场社交

牧场社交是 P3 的最高优先级外围循环，放在进化之后。

> 1.3.2 覆盖说明：下方内容保留为首版设计历史。当前运行规则已经简化为“双精灵 + 三场所 + 1 小时 + 性格学习”，不再结算亲密度、关系等级、资源、侵蚀、吞噬、繁育或数量型结果；以 `docs/1.3.2版本修改内容记录.md` 为准。

第一版设计目标：

- 玩家把两只怪物放入一个社交场所。
- 经过一段时间后，系统根据性别、属性、性格结算不同结果。
- 初始只开放 1 个社交场所，后续可以通过进度增加场所数量。
- 产出先采用低风险收益：怪物经验、金币、捕捉/经验/进化相关道具和结果记录。
- 第一版不直接产出新怪物，避免在数值和继承规则未验证前引入繁育复杂度。

当前第一版代码契约：

- `SocialRules` 负责社交时长、性别推导、相性评分、预览和结算结果。
- 怪物实例新增 `gender` 字段；旧实例会按实例 ID 和物种稳定推导性别，兼容旧存档。
- 牧场状态新增 `social_places`，第一版固定 1 个场所。
- 牧场“怪物课堂”右下入口进入“社交庭院”，可放入两只怪物并开始/领取社交结果。
- `SaveManager.start_social()` 与 `collect_social()` 负责持久化计时和发放奖励。

## 7.5 进化体验优化

进化体验优化是 P3 的第二个高优先级切片，用来把“社交、养成、战斗玩法变化”连接起来。

> 1.3.2 覆盖说明：社交领取不再新写入 `evolutionInsight`；旧存档字段仍可读取，进化条件、属性/玩法预览与进化历史继续保留。

第一版设计目标：

- 进化前必须展示目标形态、条件、属性增量和玩法变化，避免玩家只看到战力跳字。
- 社交完成后给参与怪物留下 `evolutionInsight`，作为下一次进化的情感与组合反馈。
- 进化后生成 `evolutionReport` 与 `evolutionHistory`，记录从哪只怪物进化、获得了什么玩法变化、是否消耗过社交启发。
- 第一版社交启发不直接增加永久属性，先作为可读反馈和后续分支进化/羁绊系统的接口，避免未验证前破坏数值平衡。

当前第一版代码契约：

- `EvolutionRules` 负责进化预览、属性差异、技能角色变化、社交启发文案和进化历史条目。
- 怪物实例新增 `evolutionInsight`、`evolutionHistory`、`evolutionCount` 字段，并兼容旧实例归一化。
- `SaveManager.collect_social()` 会给参与社交的两只怪物写入进化启发。
- `SaveManager.evolve_instance()` 会生成进化报告、消耗进化启发并记录历史。
- 牧场“怪物课堂”和独立进化场景都会展示进化玩法变化与社交启发。

## 7.6 牧场定向追赶与陪伴收益

牧场定向追赶与陪伴收益是 P3 的第三个高优先级切片，用来让牧场从“后台经验桶”变成有选择的养成场所。

第一版设计目标：

- 玩家可以在牧场中指定一只已放置怪物为“专注培养”对象。
- 专注对象如果低于当前队伍最高等级 2 级或以上，吃成长追赶倍率。
- 牧场中放置多只怪物时，所有放置怪物获得陪伴经验加成。
- 第一版只改经验收益，不直接增加永久羁绊属性，避免后台收益绕过战斗构筑。

当前第一版代码契约：

- `RanchCareRules` 负责牧场基础收益、专注追赶倍率、陪伴倍率和显示标签。
- 牧场状态新增 `care_focus_instance_id`，只允许指向当前牧场槽位里的怪物。
- `SaveManager.get_ranch_care_state()` 暴露每只牧场怪物的收益状态。
- `SaveManager.get_idle_exp_rate_for_instance()` 使用照料规则计算实际挂机收益。
- 牧场挂机累计最多 8 小时，超过后不继续增加可领取收益；UI 的放置时间同样以 8 小时封顶显示。
- 牧场页左下按钮改为“专注”，选中牧场槽位后可设置或取消专注培养。

## 7.7 图鉴生态目标体验

图鉴生态目标体验是 P3 的第四个切片。本轮按用户要求暂缓奖励口，先把“玩家为什么继续收集、下一只该找谁”讲清楚。

第一版设计目标：

- 图鉴“目标”页展示角色组目标和生态目标，不发放奖励。
- 生态目标展示已拥有/总数、完成状态、生态主题和下一只缺口。
- 角色组目标提示输出/守护/控场三类核心角色是否齐备。
- 第一版只做目标可读性和行动建议，奖励、领取状态、红点和经济投放后续再接。

当前第一版代码契约：

- `EcologyBondRules.get_ecology_targets()` 生成生态目标、缺口、下一只建议和完成状态。
- `EcologyBondRules.get_role_collection_target()` 生成开拓角色组目标。
- 图鉴底部第三页从“收藏”调整为“目标”，展示目标列表和下一只建议。
- 测试明确要求第一版目标数据不暴露 `reward` 字段，避免提前接入奖励口。

## 7.8 羁绊分支与社交字段

羁绊分支是牧场社交深度优化的前置骨架。第一版目标不是立刻给战斗加数值，而是先让每只怪物具备可累积的社交记忆、社交风格和羁绊标签，让后续场所、事件、关系等级和分支进化有稳定数据可读。

第一版设计目标：

- 怪物实例持有 `socialProfile`、`bondTraits`、`bondMemory`，不再只依赖物种静态数据。
- 牧场社交领取后写入双方关系记忆，记录搭档、历史最高相性、最近标签和社交经验。
- 队伍羁绊从单一提示升级为“分支”表达，例如开拓分支、压制分支、生态分支、同伴分支和性格默契分支。
- 第一版分支只做可读目标与构筑方向，不暴露 `statBonus`，避免在未验证前改变 P0/P1 战斗平衡。

当前第一版代码契约：

- `MonsterPool` 创建和归一化实例时会补齐 `socialProfile`、`bondTraits`、`bondMemory`。
- `MonsterService.build_instance_view()` 向 UI 暴露性别、社交档案、羁绊标签、关系记忆、战斗角色和生态身份。
- `SaveManager.collect_social()` 在发放社交结果后写入双方社交经验和伙伴记忆。
- `EcologyBondRules.calc_team_bond_branches()` 根据队伍角色、生态、社交经验和羁绊标签生成分支列表。
- 队伍编成页显示当前队伍优先分支，玩家能看到“为什么这三只可以放在一起”。

后续深度优化方向：

- 增加多种社交场所，让场所偏好影响相性、事件和成长方向。
- 增加关系等级与事件文本，让重复搭档有长期差异。
- 将羁绊分支逐步接入捕捉稳定度、Boss 破招提示、进化启发或章节机制抗性。
- 奖励口继续暂缓，先完成体验、字段和关系反馈。

## 7.9 牧场社交深度优化第二版

牧场社交第二版的目标，是把“放两只怪物等时间”推进为“选择合适场所、观察关系变化、积累可被后续系统读取的事件记忆”。本阶段继续不扩大奖励口，优先做玩家能看懂、系统能沉淀的数据。

第一刀设计目标：

- 初始仍只有 1 个社交位，但社交位可以切换场所类型。
- 场所影响相性评分、事件主题和关系成长表达。
- 不同社交场所有不同完成时间，第一版为草坪庭院 1 小时、暖阳广场 2 小时、静水池 6 小时。
- 社交结果生成事件，包括事件名、主题、摘要和后续影响说明。
- 两只怪物之间形成关系阶段：初识、熟悉、亲近、羁绊。
- 关系阶段和事件写入 `bondMemory.partners`，为后续分支进化、捕捉稳定度或 Boss 破招反馈预留口。

当前第一刀代码契约：

- `SocialRules` 新增 `PLACE_CONFIGS`、`PLACE_ORDER` 和关系等级规则。
- `SocialRules.preview()` 与 `resolve()` 支持读取场所，输出 `place_id`、`place_name`、`duration_ms`、`duration_label`、`relation_level`、`relation_label` 和 `event`。
- `SaveManager.cycle_social_place()` 支持在未开始社交时切换当前场所。
- `SaveManager.collect_social()` 结算时将关系等级、场所和事件摘要写入双方伙伴记忆。
- 牧场社交庭院 UI 显示场所名、场所偏好、预计关系、预计事件和上次事件。

当前内容库框架：

- `SocialRules.EVENT_CATALOG` 是社交事件的内容源，每条事件包含 `id`、适用场所、关系门槛、分数门槛、触发标签、事件名、主题、叙事文本、结果说明和后续系统钩子。
- 当前已配置 11 条事件，覆盖草坪庭院、暖阳广场、静水池，以及亲近/羁绊级跨场所事件。
- 社交事件会按场所、相性标签、分数和关系等级选择最合适的一条，不再只是生成通用文案。
- 社交结果新增 `majorOutcome` 框架，用于承载会改变怪物池的高价值结果；当前已实现 `birth` 和 `erosion`。
- `birth` 会生成 1-2 只 Lv.1 复合幼体，写入 `lineage`、`mutationTraits` 和 `source=social_birth`。
- `erosion` 会识别危险倾向怪物可能吞噬另一只怪物的风险，但默认保护会阻止自动删宠。当前只展示风险警报并保留双方怪物；后续如开放高风险玩法，必须增加玩家主动确认流程。
- `bondMemory.partners` 现在记录 `lastEventFlavor`、`lastEventOutcome` 和 `lastEventHook`，为关系详情、分支进化和后续羁绊效果保留内容依据。
- 社交庭院 UI 已展示事件名、主题、系统钩子和叙事文本，让玩家在开始前或领取后能读到“这次发生了什么”。
- 社交完成领取后会弹出结果画面，展示事件、相性、收益，以及生育/侵蚀等特殊结果。
- `SocialRules.build_relationship_detail()` 输出当前关系、历史次数、最高相性、最近事件和下一次预期，用于 UI 和后续测试。
- 社交庭院新增关系详情面板：无历史时显示预计关系、预计分数和预计事件；有历史时显示当前关系、社交次数、最高相性、最近事件和系统钩子。

下一刀方向：

- 当前已完成默认社交保护和风险提示；后续如开放侵蚀收益，需要增加独立的玩家主动确认流程。
- 让场所选择从“循环切换”升级为可扩展场所列表，并与进度解锁挂钩。
- 将关系等级轻量接入进化启发或羁绊分支提示，但仍暂缓经济奖励扩张。
