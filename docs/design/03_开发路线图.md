## 1. 开发原则

1. 先统一核心契约，再扩内容。
2. 先把前 30 分钟做出吸引力，再谈长章节铺量。
3. 每个阶段都要有可玩的验收版本。
4. 新系统必须同时考虑 UI 反馈、数值验证和数据配置方式。

## 2. 总阶段

## Phase 0：设计接手与旧口径封存

### 目标

让团队只有一套当前设计依据。

### 产出

- 旧文档归档
- 新设计总纲
- 新核心玩法文档
- 新数值留存框架
- 新开发路线图

### 状态

- 已完成

## Phase 1：核心战斗契约重构

### 目标

解决“棋盘规则、怪物属性、技能职责”互相脱节的问题。

### 任务

1. 建立幻想属性与棋盘能量的双层字段
2. 为现有怪物补充棋盘亲和字段
3. 统一属性映射、克制和技能充能读取路径
4. 将主动技能数据从纯倍率升级为效果类型
5. 先改初始三只怪物和第一批进化怪物
6. 统一星级、奖励、捕捉公式源

### 代码影响面

- `src/data/monster_db.gd`
- `src/match3/board.gd`
- `src/battle/battle_manager.gd`
- `src/battle/damage_calculator.gd`
- `src/battle/capture_system.gd`
- `src/ui/scene/scene_battle.gd`
- `src/ui/controllers/result_logic.gd`

### 验收

- 后期幻想属性怪物不再因为棋盘无对应宝石而失去基础行动
- 初始三只怪物技能体验明显不同
- 捕捉、结算、奖励只有一套规则结果

## Phase 2：前 30 分钟纵向切片

### 目标

做出一个能让玩家记住的开局，而不是一个功能清单。

### 任务

1. 重编 Ch1-Ch2 关卡教学节奏
2. 在 Ch1 实装捕捉窗口
3. 给敌人加入可读意图展示
4. 让首个 Boss 有明确破招点
5. 让战斗准备界面显示真实克制、角色和关卡压力
6. 补足新手期奖励与首个构筑选择

### 验收

- 60 秒内首胜
- 5 分钟内首次捕捉
- 10 分钟内玩家看到技能职责差异
- 30 分钟内玩家打过一个需要判断的 Boss

## Phase 3：捕捉、养成与生态循环

### 目标

让收集怪物变成持续玩下去的动力。

### 任务

1. 捕捉结果反馈失败原因
2. 怪物增加捕捉偏好与生态标签
3. 进化加入玩法升级反馈
4. 牧场改成定向追赶和陪伴收益
5. 图鉴增加生态进度目标
6. 新捕捉怪物加入追赶机制

### 验收

- 玩家愿意为捕捉目标调整队伍或局内选择
- 新怪物不会因等级落后而长期无法试用
- 进化带来一个玩法变化，不只是战力跳字

## Phase 4：章节机制管线

### 目标

用可复用的规则管线生产有记忆点的章节。

### 任务

1. 建立章节机制模板
2. 建立关卡目标模板
3. 建立敌方意图模板
4. 建立 Boss 三层结构模板
5. 复核障碍物、锁定宝石、毒雾等机制的入场顺序
6. 重新规划中后期章节生态和奖励

### 验收

- 每章能用一句玩法话术描述
- 普通关、精英关、Boss 不是同一题反复加数值
- 新章节接入不需要复制大量硬编码规则

## Phase 5：数值验证与留存打磨

### 目标

把游戏从“能玩”推到“愿意反复玩”。

### 任务

1. 建立关键关卡模拟与回归用例
2. 输出阶段数值表
3. 校准金币、经验、捕捉道具和扫荡收益
4. 校准星级评价与玩家目标
5. 校准日常奖励、牧场收益和成长追赶
6. 根据实测调整失败率和局长

### 验收

- 关键节点局长落在数值框架目标范围内
- 卡关原因可解释
- 长线资源没有明显爆仓或断供

## Phase 6：表现与可传播点

### 目标

把有创意的机制做成玩家能感知、愿意分享的瞬间。

### 任务

1. 强化连锁、破招、捕捉窗口的表现
2. 强化 Boss 意图预告和反制反馈
3. 强化怪物技能的专属动画语言
4. 强化章节生态展示
5. 打磨首局、首捕、首进化的仪式感

### 验收

- 玩家能从视频片段看出本作不是普通三消换皮
- 关键事件不靠说明文字解释也能看懂

## 5. 决策闸门

进入下一阶段前必须回答：

1. 当前版本是否比普通三消怪物复刻更有记忆点？
2. 玩家是否在局内做出了至少两个不同类型的判断？
3. 玩家是否愿意为一个怪物玩法身份而不是纯战力去捕捉或培养它？
4. 现有数值是否可以通过测试或模拟复核？
