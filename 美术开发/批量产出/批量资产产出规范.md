# 批量资产产出规范

## 1. 资产分级

| 等级 | 用途 | 文件要求 | 当前状态 |
| --- | --- | --- | --- |
| 概念图 | 确定模块效果与风格 | 整屏 PNG | 已完成 |
| 概念裁切 | 占位、试接入、拆解参考 | 矩形 PNG，可带背景 | 已完成 |
| 正式素材 | 游戏内长期使用 | 透明 PNG / WebP / 九宫格 / 序列帧 | 待产出 |
| 图集素材 | 性能优化与发布 | atlas PNG + JSON | 待产出 |

## 2. 正式资产命名

建议统一使用英文小写与下划线：

```text
ui_btn_primary_normal.png
ui_btn_primary_pressed.png
ui_panel_blue_9s.png
gem_fire_normal.png
gem_fire_enhanced.png
monster_fire_lizard_idle_01.png
fx_fire_combo_01.png
map_chapter_01_grassland.png
```

## 3. 推荐尺寸

| 类型 | 推荐尺寸 | 说明 |
| --- | --- | --- |
| 宝石 | 96x96 或 128x128 | 游戏内缩放到棋盘格，保留高分辨率源 |
| 怪物头像 | 192x192 | 图鉴、队伍、战斗卡共用 |
| 怪物半身/战斗立绘 | 384x384 或 512x512 | Boss可更大 |
| 普通按钮 | 240x88 | 可拆九宫格按钮底和文字 |
| 小图标 | 64x64 | 背包、商店、属性、货币 |
| 面板 | 按 9-slice 输出 | 程序用拉伸绘制，减少多尺寸重复 |
| 特效 | 128x128 / 256x256 序列帧 | 火焰、闪电、治疗、护盾、捕获 |

## 4. 批量生成提示词基准

```text
原创Q版像素风移动游戏资产，深蓝幻想UI体系，明亮元素色，高对比清晰轮廓，适合微信小游戏Canvas渲染。
输出单个独立资产，居中，透明背景，边缘干净，无文字，无水印，不引用任何现成怪物IP。
保持与概念图一致：深蓝面板、金色描边、火/水/草/雷/光五元素。
```

## 5. 批量顺序

1. 先产出五元素宝石和障碍物，因为它们直接影响核心战斗可读性。
2. 再产出初始三只怪物与Boss，替换当前 `monsterData.js` 的 emoji 展示。
3. 产出 UI 面板、按钮、图标九宫格，统一全部场景的视觉层级。
4. 产出章节地图节点、奖励图标、捕获球、进化石。
5. 最后做特效序列帧与动效参数。

## 6. 程序接入建议

- 新增资源表，例如 `js/data/assets.js`，维护 asset id 到路径的映射。
- `renderer.js` 增加图片缓存与 `drawImageAsset(id, x, y, w, h)`。
- `board.js` 的 `GEM_EMOJI` 逐步替换为 `GEM_ASSET`。
- `monsterData.js` 中为怪物增加 `iconAsset`、`battleAsset`、`portraitAsset`。
- `items.js` 中为道具增加 `iconAsset`。
